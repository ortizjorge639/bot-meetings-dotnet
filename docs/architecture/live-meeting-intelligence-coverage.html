Meeting Intelligence POC Coverage

Comparison of the current V1 POC, the next POC, and the initial solution intent.

Summary: V1 proved the Teams and post-meeting transcript path, including a deployed chat model that could answer from the completed transcript. It did not prove live spoken-content access, rolling context, scheduled summaries, retrieval, or question answering while context is still changing.

Observed mid-meeting Graph result

Tested September 23, 2026 at 20:21:41 UTC.

GET /transcripts returned 200 OK with an empty collection while the transcribed meeting was active.

Conclusion for the tested meeting: Graph exposed no transcript resource, transcript ID, or VTT content that could be supplied to the agent during the meeting.

This is empirical evidence for the tested tenant and meeting. It is not a guaranteed mid-meeting response contract. Microsoft documents transcript retrieval as a post-meeting capability.

What V1 proved

Proven

  • Teams bot hosting and endpoints
  • Meeting lifecycle events
  • Meeting and organizer identity
  • Post-meeting Microsoft Graph transcript retrieval
  • Retry of delayed transcript publication
  • WebVTT parsing and transcript chunking
  • File-backed POC persistence
  • Proactive Teams transcript output
  • Deployed chat-model integration
  • Answers grounded in a completed meeting transcript

Not proven

  • A supported non-Graph source for live spoken content
  • Model-generated summaries
  • Rolling meeting state
  • Q&A from continuously changing live context
  • Semantic or vector retrieval
  • Distributed scheduling and scale-out
  • Editable Markdown instructions
  • Live-to-official transcript reconciliation
  • Quality, cost, latency, and operational targets

Instruction publishing for this POC

No custom administration UI is needed yet. Store versioned Markdown files in a private Blob Storage container and use Storage Explorer or the Azure portal to publish them. Record the instruction version on each generated result. Build a dedicated UI only if later evidence shows nontechnical publishing, approvals, or previews are required.

Next proof sequence

  1. Feed simulated utterances into rolling state.
  2. Generate summaries every 30 seconds.
  3. Generate condensed summaries every 2 minutes.
  4. Post each result through the reused Teams notification path.
  5. Add embeddings and search for grounded Q&A.
  6. Validate a supported source of live spoken content.
  7. Reconcile live content with the official Graph transcript.
  8. Use collected measurements to define targets and production intervals.
The 30-second and 2-minute intervals are accelerated POC settings, not production commitments. No quality, latency, or cost targets have been selected yet.
